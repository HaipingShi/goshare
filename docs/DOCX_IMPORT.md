# DOCX 上传与文章解析

首页选择 `.docx` 文件 → 浏览器本地解析 → 点击“渲染预览” → 检查正文 → 生成分享链接。在预览或分享正文页点击“AI 分析全文”，即可提炼智能目录及思维导图；也可使用原文标题目录。

## 保留内容

- Word 标题样式转为 H1–H6，包含英文 Heading 与中文“标题”样式；正文保留粗体、斜体、链接等基础语义格式。
- 有序列表、无序列表、嵌套列表。
- 表格、表头及合并单元格。
- 内嵌 PNG、JPEG、GIF、WebP 图片和替代文字。图片转换为 data URI，与文章一起存入 R2，刷新、分享和后台编辑不会丢失临时图片链接。
- 转换器可识别的脚注与尾注链接。

转换保留文章结构，不复刻 Word 的字体、分页、页眉页脚、浮动排版或复杂图形。使用 Word 标题样式才能可靠识别标题。旧版 `.doc`、密码加密文档、ZIP64 和 WMF/EMF 等非浏览器图片不支持；图片问题和解析警告会显示在首页。

## 数据与限制

解析器基于 [Mammoth](https://github.com/mwilliamson/mammoth.js)，随站点静态资源提供，按需加载。原始 DOCX 在浏览器中解析，不发送给第三方转换服务；服务器仅接收转换后的文章。原始 Word 文件不会另行保存。

原文件最大 10MiB、最多 2,000 个包内条目；单条目解压最大 20MiB，总解压最大 50MiB。解析前检查目录，再通过流式解压核对实际体积，拒绝重复路径、损坏或伪造大小的压缩包。包含 base64 图片的解析结果最大 10MiB（UTF-8 字节），DOCX 预览使用相同限制，其他文本预览继续限制为 512KiB。

DOCX 文章在预览、创建、后台编辑及阅读时均由服务端 HTML 白名单过滤，移除脚本、事件、CSS、危险链接和外部/SVG 图片。禁用文档内自定义 Mammoth 样式映射及外部文件读取。普通网页分享仍使用原有渲染流程。

AI 会读取全文文字、表格文字和图片替代说明，不分析图片像素。复用 [文章分析接口](ARTICLE_READING.md)，受 64K 字符、400 文本块和每日 AI 额度限制；超长文章需拆分。AI 失败时仍可阅读原文和使用标题目录。通过首页工作流生成的分析与图形随文章保存，刷新后恢复；阅读页临时分析仍仅保存在页面内存。

DOCX 使用文章页的“AI 分析全文”，首页整页“智能美化”对 DOCX 禁用，避免模型改写文章时丢失图片或原文结构。

## 构建与接口

`npm ci` 的 postinstall 自动生成 `public/js/docx-import.js`；`npm run dev`、`check`、`check:production` 和 `deploy` 也会先构建。生成文件已加入 Git 忽略，由锁定的 npm 依赖重建。如跳过 npm 生命周期，先执行 `npm run build:docx` 再运行 Wrangler。

API 中 `codeType: "docx"` 表示**已转换的文章 HTML 片段**，`htmlContent` 不接受 DOCX 二进制或 base64 压缩包。支持与 Markdown 相同的 `markdownTheme` 参数。D1 继续使用现有 `pages.code_type` 文本字段，无需迁移；R2 保存过滤后的文章，后台可编辑文章 HTML。

自动测试使用合成 DOCX 实际解析，覆盖双语标题、嵌套/有序列表、合并表格、内嵌图片、非法压缩包、服务端过滤和含图预览体积限制。
